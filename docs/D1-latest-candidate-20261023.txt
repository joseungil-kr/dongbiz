  Non-null collected_at matches the prior COUNT(DISTINCT collected_at)>=1 rule.

  The directory is ordered by keyword, not latest observation, and retains exact
  spacing variants. Related-link ties use this new directory order.
  Unregistered historical user keywords are no longer advertised by the directory,
  related links, sitemap or bulk IndexNow. Their exact public/admin URLs continue
  to work when valid data exists. Existing comment keys remain in the admin list.
  Empty/unpublished/ads-only/analytics-only/null-date data does not produce a valid
  detail page. Existing one-observation rendering and first-page metrics remain.

Canonical and comment identity
  The old canonical representative changed with greatest observation count and
  was also used as the comment key. The new canonical/breadcrumb/og:url use the
  exact requested keyword, with no tracking parameters.
  Comment lookup first honors the exact stored key, including a private comment.
  With no exact key, a single whitespace-normalized existing comment is reused.
  With multiple such keys, none is arbitrarily chosen. No stored key is moved,
  deleted, merged, or re-assigned based on observation counts.
  Public rendering still requires approved===1. An exact private comment cannot
  accidentally fall back to an approved alias. Admin editing uses the resolved
  storage key and displays a notice when editing a shared spelling variant.
  Admin authentication, save validation, toggle and noindex,nofollow remain.
  Missing comment-table compatibility remains for detail reads; other DB errors
  continue to fail rather than masquerade as successful empty statistics.
  Tradeoff: whitespace variants may be semantically duplicate and are not merged
  for SEO. If multiple old comment keys exist, a non-exact variant no longer gets
  whichever comment happened to win by observation count. Exact keys stay editable.
  Production prevalence of these cases has not been measured.
