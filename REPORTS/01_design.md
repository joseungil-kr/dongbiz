# 1단계 URL·페이지 설계

기준: SPEC.md 전체(2026-11-23). 이번에는 3·5·6절 산출물만 작성한다. 기존 worker 라우트·가이드·D1 스키마는 변경하지 않는다.

## 라우트와 페이지 구조

- /cost: 지역·업종별 15편 허브. H1은 “철거·원상복구 비용과 견적 비교”, title은 “철거·원상복구 비용과 견적 비교 · 동네장사”. CollectionPage + ItemList를 사용한다.
- /cost/:slug: 아래 확정 한글 slug만 사용. canonical은 https://dongbiz.com/cost/{URL 인코딩한 slug}, 허브는 https://dongbiz.com/cost.
- 상세별 title·description·canonical 및 OG/Twitter에 동일 페이지 메타를 사용한다. 확보하지 않은 이미지 URL은 만들지 않는다.
- 상세 JSON-LD는 Article + BreadcrumbList + 본문에 표시한 질문·답변의 FAQPage. 브레드크럼은 홈 › 철거·원상복구 비용 › 현재 페이지.
- H1 하나, 첫 문단 직답 2~3문장(id="aeo-direct-answer"), 공장 본문, 실측 업체 표, 비교 체크리스트, FAQ 순으로 구성한다. 이번 매핑은 15페이지 모두 지역 일치 실측업체 10곳을 확보했다. 업체 표는 data/page-places.json의 선정 목록을 사용한다.
- CTA “내 업체 플레이스 순위·점수 무료 진단하기” → /, “우리 업체 정보 수정·등록 문의” → /guide/플레이스정보수정순위.
- 기존 siteNav('place'), siteFooter(), 공통 CSS를 다음 실행에서 재사용한다. 다음 실행에서 sitemap에 허브 priority 0.8, 상세 15편 0.7을 추가하고 IndexNow에도 같은 16개 URL을 추가한다.
- 성공 데이터가 있을 때만 “업체 정보는 네이버 플레이스 공개 정보를 2026-11-23에 수집한 값이며, 순위는 검색 위치·시점에 따라 달라집니다.”를 표시한다. 재수집하면 실제 날짜로 갱신한다. 현재 12개 검색 모두 성공했으며 지역 일치로 확인한 업체만 표시한다.

## 내부링크 규칙과 제약

표의 cost 번호는 아래 확정표의 slug로 연결한다. 1~14는 관련 권역 3편 + 인접 권역 2편 + 15번, 총 6개다. 앞 3개가 관련 권역, 다음 2개가 인접 권역이다. 안산은 구를 포함한 안산 권역으로 묶는다. 군포는 다른 페이지가 2편, 시흥은 1편뿐이므로 같은 시 3편 조건은 확정된 15편만으로 충족 불가다. 부족분은 안산·군포·시흥 통합 권역의 관련 업종으로 보충한다. 이는 동일 시 3편을 충족한 것으로 주장하지 않는 제약이다.

모든 상세는 /cost 허브와 /guide/플레이스경쟁분석, /guide/플레이스정보수정순위에도 연결한다. rank 링크는 표에서 지정한다. 업체 링크는 data/page-places.json에 선정된 실제 /p/{placeId}만 허용한다. 페이지별 10곳이며 아래 인용 업체 링크를 본문에서 사용한다. 15번은 세 지역 업체를 한 표에 출처 키워드와 검색별 순위를 함께 표시하며 통합 순위는 만들지 않는다.
